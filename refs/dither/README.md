# 像素抖动参考库

给 AI 画渐变、色带交界、光晕、云雾、柔和边缘时查的参考：**效果图 + 文字描述**。

- 这里是真实文件，只放在项目里。Skill 里只放查询入口 `pxl ref dither`，AI 按需取某一条，不整库读入。
- 这份 README 是完整说明，主要给人看；AI 查询时拿到的是从这里摘出来的精简版。
- 进度见 [../../TODO.md](../../TODO.md)「参考库：像素抖动」一节。

---

## 1. 为什么需要它

AI 画抖动时习惯直接套公式：`(x+y)%2`、`x%4 == (y//2)%4`、固定的 Bayer 4×4 阈值。公式本身没错，但全图都这么用，结果就像机器印出来的。2026-09-10 画的 256×256 风景画（`examples/landscape.pxl`）里有这些问题：

| 位置 | 刻板在哪 | 当时的写法 |
| --- | --- | --- |
| 天空色带交界 | 每条交界都是横贯全图的笔直「花边」，宽度完全一样 | 固定几行里按 25% / 50% / 75% 切换 |
| 太阳光晕 | 固定半径的同心环，50% 棋盘格和 25% 网格在环界突然切换 | `14.5 < d < 19` 用 `(x+y)%2`，`19 ≤ d < 23.5` 用 `x%2==0 and y%2==0` |
| 雪线 | 锯齿周期完全一致 | `(x // 5) % 4 == 1` |
| 草地色带 | 每条色带同宽，只有规律的 ±2 格起伏 | Bayer 阈值加固定幅度偏移 |

参考库要教的不是「有哪些图案」，而是 **什么时候用哪种、怎么打破规律、哪些做法是错的**。

## 2. 术语

| 术语 | 含义 |
| --- | --- |
| 色阶 | 同一色系从暗到亮的几档颜色。条目里用数字 `1`–`9` 表示，**`1` 最暗，数字越大越亮**；用的时候换成自己调色板里对应的字符 |
| 密度 | 两个色阶混合时，**较暗色所占的比例**。0% = 全是亮色，100% = 全是暗色 |
| 单元 | 图案里最小的重复块，比如 50% 棋盘格的单元是 2×2 |
| 相位 | 图案相对画布原点的偏移。棋盘格的暗格落在 `(x+y)` 为偶数还是奇数的格子上，就是两种相位 |
| 带宽 | 某一档密度沿过渡方向持续的格数 |
| 边界起伏 | 两档密度之间的分界线偏离直线 / 正圆的程度 |

## 3. 按场景选择

| 场景 | 用什么 | 要点 | 条目 |
| --- | --- | --- | --- |
| 天空、大面积平涂的色带交界 | ordered（Bayer 类有序抖动） | 多档密度逐级过渡；边界按行错开；每条交界带宽不同 | `sky-band`（阶段 3） |
| 太阳、灯光的光晕 | ordered，密度随距离连续变化 | 不要同心环；外缘打散 | `glow-radial`（阶段 3） |
| 云、雾、烟的柔边 | scatter（错位稀疏点） | 密度一般 ≤25%；点不要对齐成网格 | `cloud-soft`（阶段 3） |
| 远景雾化（山脚、地平线） | ordered，沿纵向过渡 | 起止线随地形起伏，不是水平直线 | `horizon-haze`（阶段 3） |
| 树冠、草地、岩石质感 | cluster（2–3 格的团块） | 不用单格棋盘格 | `foliage`（阶段 3） |
| 水面、倒影 | lines（断续横线） | 线段长短不一 | `water`（阶段 3） |
| 雪线、积雪边缘 | 通常不抖动 | 不规则轮廓 + 一档中间色；锯齿周期要变化 | `snow-line`（阶段 3） |
| 物体轮廓、32×32 以下的小 sprite | 不抖动 | 用抗锯齿（在轮廓拐角放中间色） | — |
| 通用多色渐变参考 | — | 见第 5 节解析 | `reference-strip`（已有） |

## 4. 规则

1. **只在相邻色阶之间抖动。** 色阶 2 和 3 之间可以；1 和 4 之间抖动出来就是噪点。需要跨越多档时，逐档过渡（2↔3 抖动 → 纯 3 → 3↔4 抖动）。
2. **密度要逐级变化。** 至少经过 25% → 50% → 75% 三档，大面积可以更细（12.5% 一档）。只用一档 50% 棋盘格的过渡，只适合对比很小的两色，或者很窄的区域。
3. **带宽不要一样。** 同一幅画里多条交界，带宽要有变化；同一条交界沿着走向，带宽也要缓慢起伏。
4. **边界要打散。** 两档密度的分界不能是直线或正圆。最简单的做法是按行错开：同一种行之间切换位置错开 1–2 格（见第 5 节）；大尺度上再让整条过渡带每 8–16 格起伏 1–3 格，或者沿物体轮廓走。
5. **同一块区域内相位保持一致，不同区域不必统一。** 同一条过渡带里，图案必须按画布坐标对齐，否则会出现错位的接缝。互不相接的两段过渡可以用不同相位（参考渐变条里两段棋盘格的相位就是相反的）。
6. **按材质选抖动方式**，见第 3 节。全图只用一种图案，就会显得刻板。
7. **看尺寸。** 32×32 以下基本不抖动；64 左右谨慎使用；128 以上的大面积平涂才是抖动的主场。

### 反例清单

| 反例 | 为什么不好 | 对应规则 |
| --- | --- | --- |
| 等宽的直线花边色带（横贯整幅画） | 一眼看出是程序生成，像缝纫线 | 3、4 |
| 同心环光晕 | 像印刷网点，环界处密度突变 | 2、4 |
| 周期完全一致的锯齿边缘 | 规律性太强 | 4 |
| 所有边缘都套 50% 棋盘格 | 物体边缘发虚发脏，没有层次 | 1、6、7 |
| 高对比两色直接抖动 | 变成噪点 | 1 |
| 相接的区域相位错开 | 出现错位接缝 | 5 |

## 5. 参考渐变条解析（`reference-strip`）

来源见 [SOURCES.md](SOURCES.md)。按原图逐格还原成 `ramps/reference-strip.pxl`（92×10 格），预览 `previews/reference-strip.png`。

色阶：`1` 黑 `#000000`、`2` 深灰 `#6a6c69`、`3` 浅灰蓝 `#98acb3`、`4` 白 `#ffffff`。

| 列 | 内容 | 较暗色密度 |
| --- | --- | --- |
| 0–9 | 纯白 | 0% |
| 10–40 | 白 → 浅灰蓝，多档过渡（见下） | 实测 36%（10–18 列）→ 50%（21–26 列）→ 86%（30–38 列）→ 100%；按 4×4 单元推算的理想值是 37.5% / 50% / 87.5%，偏差来自过渡带两端各行起点不齐 |
| 41–51 | 纯浅灰蓝 | 100% |
| 52–61 | 浅灰蓝 / 深灰 50% 棋盘格，深灰在 `(x+y)` 偶数格 | 50% |
| 62–71 | 纯深灰 | 100% |
| 72–81 | 深灰 / 黑 50% 棋盘格，黑在 `(x+y)` 奇数格 | 50% |
| 82–91 | 纯黑 | 100% |

白 → 浅灰蓝这一段（第 8–42 列，前 4 行，纵向 4 行一个周期；`3` 浅灰蓝，`4` 白）：

```
     89012345678901234567890123456789012
r0  44443444344434343434343333333333333
r1  44434343434343434343434333433343333
r2  44344434443444343434343333333333333
r3  44434343434343434343433343334333433
```

它教会的东西：

- **两种行交替。** 偶数行由 25% 变成 50% 再变成纯色；奇数行由 50% 变成 75% 再变成纯色。叠起来，平均密度就有了比单一图案更多的档位。
- **切换点错开。** 同一种行之间，切换位置错开 2 列：偶数行变成 50% 的位置在第 19 列和第 21 列；奇数行变成 75% 的位置在第 27 列和第 29 列；最后一个白点在第 38 列和第 40 列。所以这段过渡的边界是阶梯状斜着走的，不是竖直线。
- **亮端点缀要稀疏。** 第 31–40 列只有奇数行每 4 列一个白点，相邻奇数行错开 2 列，密度 12.5%。
- **对比越小，过渡越简单。** 浅灰蓝 / 深灰、深灰 / 黑两处都只用了一段 10 列宽的 50% 棋盘格；白 / 浅灰蓝的亮度差最大，才用了 31 列、四档以上的过渡。

它的局限：**这是一条教学用的横向色条，不是画面。** 每段带宽都是整 10 列，过渡方向是纯水平的。直接照搬到画面里，仍然会是规则 3、4 说的等宽直线色带。实际使用时要学它的「交替行 + 错开切换点」，再叠加第 4 节的带宽变化和边界起伏。

## 7. 条目字段（`catalog.json`）

```json
{
  "version": 1,
  "title": "像素抖动参考库",
  "digest": { "scenes": [ ... ], "rules": [ ... ], "anti": [ ... ] },
  "shade_convention": "色阶用数字 1–9，1 最暗，数字越大越亮",
  "density_convention": "密度 = 两个色阶混合时较暗色所占的比例",
  "entries": [ { ... } ]
}
```

顶层字段：

| 字段 | 说明 |
| --- | --- |
| `title` | 参考库名称 |
| `digest.scenes` | 本文第 3 节的精简版，每行 `{"scene", "use", "tips", "entry"}`；`entry` 为 `null` 表示没有对应条目，条目还没做时 `pxl ref` 会标「待补」 |
| `digest.rules` | 本文第 4 节规则的精简版，一条一句 |
| `digest.anti` | 反例清单的精简版 |

`digest` 的场景、规则、反例条数必须和本文第 3、4 节一致，测试会检查。

条目字段：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | 字符串 | 唯一标识，`pxl ref dither <id>` 用它查询；场景对用 `sky-band.bad` / `sky-band.good` |
| `kind` | `tile` / `ramp` / `edge` | 可平铺单元 / 过渡带 / 场景化边缘 |
| `family` | `ordered` / `checker` / `lines` / `scatter` / `cluster` / `mixed` | 抖动类型 |
| `status` | `reference` / `generated` / `hand-tuned` / `draft` | 第三方参考 / 脚本生成 / 人工修过定稿 / 草稿 |
| `title` | 字符串 | 一句话标题 |
| `size` | `[宽, 高]` | 格子数 |
| `shades` | 对象 | 用到的色阶及示意颜色，如 `{"3": "浅灰蓝 #98acb3"}` |
| `density` | 数字或 `[起, 止]` | tile 是单个值，ramp / edge 是范围 |
| `canvas_scale` | 字符串 | 适合的画布尺寸，如 `">=128"` |
| `tags` | 字符串数组 | `--find` 关键词，中英文都写 |
| `use_for` / `avoid` | 字符串数组 | 适用场景 / 禁忌 |
| `why` | 字符串 | 为什么这样看起来自然（bad 条目写为什么刻板） |
| `lessons` | 字符串数组 | 可以迁移到画面里的做法（可选） |
| `segments` | 数组 | ramp 的逐段说明，每段 `{"cols": [起, 止], "desc": "…"}`（可选） |
| `contrast_with` | 字符串或 `null` | 成对条目的另一半 |
| `files` | 对象 | `{"pxl": "…", "png": "…"}`，相对 `refs/dither/` |
| `source` | 字符串或 `null` | 第三方来源，指向 `SOURCES.md` 的小节 |
| `recipe` | 字符串或 `null` | 用 pxl 命令复现的示例（阶段 3 补充） |
