# 像素画：pixel4ai / pxl

画布是 W×H 的格子，每格只能是调色板里的一个字符。你通过 `pxl` 命令改文件，用户通过编辑器（`pxl 文件 edit`）看着渲染效果手动改**同一个文件**。

## 调用 pxl（先读这一节）

每条命令都用下面这个路径调用。它不依赖 PATH，也**不需要问用户项目装在哪**：

```bash
${CLAUDE_SKILL_DIR}/scripts/pxl 文件.pxl 命令 [参数]
```

- 通过 Skill 加载时，`${CLAUDE_SKILL_DIR}` 已经被替换成本 Skill 的实际目录。加载时也会显示「Base directory for this skill」，两者是同一个目录。入口脚本会顺着软链接自己找到 pixel4ai 项目。
- 如果你看到的还是字面量 `${CLAUDE_SKILL_DIR}`（比如是直接读了这个文件，而不是通过 Skill 加载），按顺序换用第一个能跑通的：
  1. `pxl`（`command -v pxl` 能找到时）
  2. `~/.claude/skills/pixel-art/scripts/pxl`
  3. `python3 ~/Projects/pixel4ai/bin/pxl`
- Bash 工具的每次调用之间**不保留 shell 变量**。不要先 `PXL=...` 再在下一次调用里用 `$PXL`，每条命令都写完整路径。
- 下文示例为了简洁都写成 `pxl`，执行时换成上面的路径。
- 画出来的文件放在用户指定的位置；用户没说时，放在当前工作目录。除非用户明确要求，不要写进 pixel4ai 仓库自己的目录（比如 `examples/`）。
- 入口脚本报「找不到 pixel4ai 项目」：说明 Skill 是被复制安装的，让用户运行项目里的 `install.sh`，或设置 `PIXEL4AI_HOME=项目目录`。

## 基本约定

- 命令格式：`pxl 文件.pxl 命令 [参数]`，**文件写在命令前面**。
- 坐标 `(x, y)` 从 0 开始，原点在左上角，x 向右，y 向下。矩形、区域的两端都包含：`rect 2 2 5 5` 是 4×4。
- `.` 是透明。`?` 只在 stamp / rows 的行数据里用，表示「这格不动」。
- 每次修改后会打印：改了几格、改动范围，以及带坐标尺的视图。**每次都要读这份视图核对**，不要凭记忆假设画面状态。
- 所有修改都能撤销：`pxl 文件 undo [N]`，也可以 `redo`。

## 工作流程

1. **规划**：先想好尺寸和调色板再动手。
   - 尺寸：图标 16–32，角色 32–64，场景和插画 128–512，上限 1024×1024。超过 64 的画布见下面「大画布」一节。
   - 调色板：总共 6–12 色，每个主色准备 2–3 档明暗。可以用预设 `--palette pico8`，也可以用 `palette set` 自己定。
2. **创建**：`pxl hero.pxl new 16 16 --palette pico8`
3. **按部件分层画**，每层用一次 `apply`：剪影/大色块 → 1px 描边 → 固有色 → 阴影和高光 → 细节（眼睛、纹理）。
4. **每层画完先核对**：看回显的视图。**高光、斑点、眼睛这类贴着轮廓的细节，一定要先看过轮廓那一层的视图再定坐标**。椭圆轮廓落在哪些格子上是算出来的，猜坐标很容易盖掉描边。位置拿不准时，用 `view --region X0 Y0 X1 Y1 --spaced` 局部放大，逐格数清楚。错了就用 `px` / `stamp` 局部修，或者 `undo`。
5. **对称物体只画左半边**（x 不超过中线），然后 `mirror lr`。宽为奇数时中线那一列保持不动。
6. **导出**：`pxl hero.pxl export png --scale 16`。如果你能看图片，就读一下这个 PNG，检查整体观感（轮廓是否清楚、比例是否对、颜色是否太散），不要只看字符。
7. **交付**：告诉用户文件路径和 PNG 路径，并提示可以用 `pxl hero.pxl edit` 打开编辑器手动修改。

## 和用户协作

- 用户可能在编辑器里改过文件。**动手前先 `pxl 文件 view` 或 `info`**，以磁盘上的最新内容为准。
- 用户说「(3,4)-(8,9) 这块」「选区 (3,4)-(8,9)」，这是编辑器选区复制出来的坐标，含义和命令里的区域完全一样：`--region 3 4 8 9`。
- 用户说「改完了」「我调了一下」：先 `view`，再根据他们的改动继续，别覆盖掉。
- 编辑器会自动刷新你的修改，所以不用让用户重新打开。

## 命令速查

| 命令 | 说明 |
| --- | --- |
| `new W H [--palette mono\|pico8\|gb\|none] [--force]` | 创建画布；`--force` 覆盖已有文件（旧内容可 undo 找回） |
| `view [--region X0 Y0 X1 Y1] [--spaced]` / `info` | 看网格 / 看尺寸、每色用量、内容范围 |
| `palette` / `palette set C RRGGBB [C RRGGBB ...]` / `palette rm C [--replace-with D]` | 调色板 |
| `px X Y C [X Y C ...]` | 单格，一次可以给多组 |
| `line X0 Y0 X1 Y1 C` | 直线 |
| `rect X0 Y0 X1 Y1 C [--fill]` | 矩形，默认只画边框 |
| `ellipse X0 Y0 X1 Y1 C [--fill]` | 内切于矩形的椭圆/圆 |
| `fill X Y C` | 油漆桶（4 连通） |
| `replace A B [--region ...]` | 换色 |
| `stamp X Y` + 行数据 | 从 (X,Y) 贴一块子网格；每行长度可以不同，`?` 表示不动 |
| `rows Y` + 行数据 | 从第 Y 行起整行覆盖，**每行必须正好等于画布宽** |
| `mirror lr\|rl\|tb\|bt [--region ...]` | 把一半镜像到另一半 |
| `flip h\|v [--region ...]` / `shift DX DY [--wrap]` / `resize W H [--anchor c]` | 变换 |
| `clear [C]` / `undo [N]` / `redo [N]` | 清空 / 撤销 / 重做 |
| `export png [OUT] [--scale N] [--grid] [--bg RRGGBB]` | PNG（默认同名 .png，每格 8px） |
| `export ascii [OUT] [--ramp]` / `export ansi` | 字符原样输出 / `--ramp` 亮度字符画 / 终端真彩色 |

加 `-q` 可以不打印视图，适合连续的小改动。

## 批量：apply（优先用它）

一次调用执行多条命令，**全部成功才保存**；中途出错会指出第几行，文件保持不变。

```bash
pxl slime.pxl apply <<'EOF'
# 剪影
ellipse 2 5 13 14 g --fill
rect 2 11 13 14 g --fill
# 描边和阴影
ellipse 2 5 13 14 f
replace g f --region 9 10 12 13
# 眼睛：stamp 块以单独一行 end 结束，块内每行都是数据（没有注释）
stamp 5 8
k??k
k??k
end
px 4 6 w 5 6 w
EOF
```

- heredoc 要写成带引号的 `<<'EOF'`，这样 `#`、`$` 都会原样传进去。
- 脚本里以 `#` 开头的行是注释。但 `palette set # 222222` 这种参数里的 `#` 没问题。
- 直接在命令行里用 `#` 当颜色字符时要加引号：`pxl a.pxl px 1 1 '#'`。
- 小图（大约 16×16 以内）可以直接用 `rows 0` + 全部行一次写完，但每行长度必须等于画布宽。行写得越长越容易数错，所以大图用几何命令加 stamp。

## 大画布（超过 64×64，最大 1024×1024）

- **文字视图会自动缩略**：`view` 和修改后的回显，一旦超过 64 行或列，就变成缩略视图。每个字符代表 N×N 格，显示块内最多的非透明颜色。行号是原图 y；列号竖着写，从上往下读就是原图 x。缩略视图只适合看布局。**要定精确坐标，用 `view --region X0 Y0 X1 Y1`**，区域不超过 64×64 时会逐格显示。
- **修改后只回显改动附近**，改动范围太大时也会缩略。大量连续修改时加 `-q`，每做完一个阶段再 `view` 或导出 PNG 检查。
- **能看图就看图**：`export png --scale 2`（512 的画布导出 1024px）然后读图，比读字符可靠得多。
- **先规划区域再动手**：把画面按区域定好坐标范围（比如天空 y 0–199、远山 y 150–320、地面 y 400–511），逐个区域 `apply`。
- **大结构用几何命令搭**：rect、ellipse、line、fill、replace、mirror。`stamp` 只画几十格以内的局部细节。不要用 `rows` 写整行，512 个字符的行一定会数错。
- **细节放大核对**：画完一个区域，用 `--region` 看交界处和轮廓，再补细节。

## 抖动、渐变与柔和边缘

画渐变、色带交界、光晕、云雾或柔和边缘之前，**先查参考库，不要自己套 `(x+y)%2` 这类公式**：

```bash
${CLAUDE_SKILL_DIR}/scripts/pxl ref dither                # 按场景选择 + 规则 + 反例（≤30 行）
${CLAUDE_SKILL_DIR}/scripts/pxl ref dither <条目>         # 单个条目：做法、禁忌、预览图路径
${CLAUDE_SKILL_DIR}/scripts/pxl ref dither --find 光晕    # 按关键词找条目和场景
```

需要看效果时，只读条目给出的那一张预览图。不要列出或读取整个参考库目录。

## 画面规则

- **轮廓**：1px 描边，用该物体颜色的最暗一档，不一定是纯黑。内部结构线用比填充色暗一档的颜色。
- **光源固定在左上**：左上边缘提亮，右下边缘和物体下方压暗。不要沿轮廓一圈圈变暗（pillow shading）。
- **斜线**：步长保持规律（1:1、1:2、2:1），不要出现 1-3-1-2 这种锯齿（jaggies）。曲线的步长要逐渐变化。
- **少即是多**：颜色越少越统一。孤立的单格像素只用作高光或眼睛。
- **可读性优先**：先保证剪影一眼能认出来，再加细节。16×16 里眼睛通常 1–2 格就够了。
- **别过度使用纯黑纯白**：阴影用偏冷或偏紫的暗色，高光用偏暖的亮色，画面更生动。

## 常见错误

- 数错列：长字符串里的列号很难数准。用坐标尺视图，或者 `--spaced --region` 局部放大核对。
- 以为操作成功了：每次都看回显里的「改动 N 格 (范围)」。改动 0 格或者范围不对，说明坐标或颜色写错了。
- 忘了文件可能被用户改过：每次动手前先 view。
